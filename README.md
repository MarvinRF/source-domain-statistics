# Source-Domain Statistics, Not the Target Catalog

Code for the paper *"Source-Domain Statistics, Not the Target Catalog: What Geometric Corrections Do in
Zero-Shot Text-Based Cross-Domain Recommendation"* (under review at ACM TOIS).

A user's source-domain history (books) is embedded with a frozen text encoder, mean-pooled into a
query, and used to retrieve items from a target catalog (music, movies, video games) that the user has
never interacted with. The study asks what post-hoc geometric corrections (centring, all-but-the-top,
partial and full ZCA whitening) do in this setting, on which side of the retrieval pair they should
act (the query, the item catalog or both), with statistics from which population (training users, the
book catalog or the target catalog), and how the answer depends on how relevance is defined (exact
item or category). Summary of the findings:

- Metrics by category reward homogenised lists: a constant list of the most frequent category beats
  every method; this holds most clearly in music, where the categories are genres.
- Per item, the correction that works is to normalise the query with statistics of the source side
  (training users or the book catalog); it beats whitening the target catalog in 8 of 8 verified
  encoders, centring gives most of the gain, and the pattern is consistent with a reduction of
  hubness (a correlational diagnostic).
- The resulting signal is not significantly different from a lexical title matcher, it lies below a
  popularity list and a profile-kNN over training users on warm items, and only content reaches cold
  items.
- Five baselines are mandatory: popularity, top-category, lexical, shuffled profiles and profile kNN.

## Installation

```bash
python3 -m venv venv && source venv/bin/activate
pip install -e ".[dev]"          # core + tests/lint
pip install -e ".[llm]"          # optional: LLM-generated profiles (H3/H4)
pip install -e ".[dla]"          # optional: query-side span analysis (spaCy)
make test
```

Python ≥ 3.11. All dependency versions are pinned in `pyproject.toml`. A CUDA
GPU is recommended for the embedding steps; whitening, evaluation, and
statistics run on CPU.

## Data

Amazon Reviews 2023 is not redistributed. See [docs/DATA.md](docs/DATA.md) for
which files to download, where to put them (`ACW_DATASETS_DIR`), and how users,
splits, and relevance are defined.

## Reproducing the paper

The full sequence, from raw files to every table, figure, number and p-value, is in
[docs/REPRODUCIBILITY.md](docs/REPRODUCIBILITY.md). In short, for the current protocol:

```bash
make data splits-new   # 5-core filtering, ground truth, disjoint 70/10/20 user splits
make embeddings        # item and book embeddings (GPU); see docs/EMBEDDINGS.md for the provenance of every file
make grid              # corrections x encoders x domains x relevance levels (per-user results)
make stats             # paired tests (sign-flip on the mean as primary, Wilcoxon complement, Holm)
make query-norm lexical knn controls hybrid mechanism taxonomy   # the experiments of the map below
make reproduce-check   # rerun one configuration and compare it with the committed result
make paper-assets PAPER_DIR=<article dir>   # tables, figures and number macros of the article
```

The per-user score files (`results/granularity/*.csv.gz`) are regenerated by these steps and are not
committed; every committed result JSON records the code commit, a dirty flag, package versions and the
SHA-256 of its inputs.

## Repository layout

```
src/acw/
  settings.py            paths, seeds, model names (environment-overridable)
  data/                  preprocessing, 5-core filtering, user splits
  embeddings/            item encoder, mean-pooled profiles
  corrections.py         centring, ABTT, PCA, partial ZCA (pure numpy)
  evaluation/            ground truth, metrics, ranking, significance tests
experiments/
  granularity/           the experiments of the map above
  figures/               tables, figures and number macros of the article
  (legacy)               main_results, register_gap, domains, robustness, encoder_sweep, training
results/                 versioned outputs (JSON/CSV) behind every reported number
tests/                   unit tests (CPU, no data needed)
docs/                    data, embedding provenance and reproducibility guides
```

Every experiment is run from the repository root as
`python -m experiments.<group>.<name>` and writes its output under `results/`.

## Evaluation protocol

- **Relevance:** the exact target items each user reviewed (primary), and, as a diagnostic, all catalog
  items that share a category at depth 1, 2 or 3 with those items; category levels are principal in
  music (genres) and auxiliary in movies and games (department, format and platform nodes).
- **Baselines (mandatory):** popularity and top-category (built from training users), a lexical title
  matcher, shuffled profiles and a profile kNN over training users.
- **Metrics:** nDCG@10 and Recall@{10, 50, 100}; cold and warm items are scored apart.
- **Statistics:** paired sign-flip test on the mean as the primary test, a bootstrap 95% CI,
  Wilcoxon-Pratt as a complement, Holm per family, the number of discordant users (`n_nonzero_diff`)
  next to every test, and signed matched-pairs rank-biserial effect sizes
  (`acw.evaluation.significance`).
